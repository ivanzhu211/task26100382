# weightledger

进程内并发重量账本：种植批次分装（Package）、销售（Sell）、退款（Refund）与一致快照（Snapshot）。
重量统一使用整数厘克（1 厘克 = 0.01 克），数据全部在内存中。

## 使用

```go
l, _ := ledger.NewLedger(
    map[ledger.BatchID]ledger.Centigram{"B1": 100000},
    map[ledger.SKU]ledger.Centigram{"A": 100}, // 单件净重 1 克
)
lot, _ := l.Package("B1", "A", 10, 50)        // 分装 10 件，废弃 50 厘克
sale, _ := l.Sell(map[ledger.SKU]uint64{"A": 4})
ref, _ := l.Refund(sale.ID, map[ledger.SKU]uint64{"A": 1})
snap := l.Snapshot()
err := snap.CheckInvariants()                  // 复核重量守恒
```

## 并发设计

- **无全局业务锁**：每个种植批次、SKU、原销售各有独立互斥锁。写操作只锁
  涉及的对象，按固定顺序加锁（批次/销售锁在前，SKU 锁按字典序在后），
  不相交的写互不阻塞、无死锁。
- **MVCC 快照**：每个可变数据是版本化 cell（不可变节点链表）。写事务在持锁
  状态下先校验、再统一提交：分配全局递增提交版本号 → 发布全部 cell →
  标记发布完成。`Snapshot` 不加业务锁：读取提交计数为目标版本，自旋等待
  连续发布前沿达到该版本（只等已分配版本的写方完成发布，不等新写操作），
  然后按版本读取各 cell，保证视图落在事务边界上，绝不混读半个事务。
- **原子性**：所有写操作先完整校验再提交；散装不足、库存不足或超额退款时
  不发布任何 cell，整笔不留变化与凭据。
- **退款**：按原销售凭据的分配顺序返还尚未退过的数量，实物回到原来源批号；
  原销售凭据不可变，退款凭据关联原销售；退回商品可再次销售；废弃重量不因
  退款冲回。

不变量（`Snapshot.CheckInvariants` 复核）：每个批次
`初始 = 剩余散装 + 在库包装净重 + 净已售 + 累计废弃`，各项非负；
在库与净已售均可由同一快照中的库存余额、销售及退款凭据复核。

## 测试

```sh
go test ./...          # 全部测试
go test -race ./...    # 竞态检测
```

测试用 channel 屏障与测试钩子（`testHooks`）控制交错，不依赖固定 sleep：

- `sell_race_test.go`：两笔销售以相反 SKU 排列竞争只够一笔的库存，
  恰好一笔成功、无死锁，失败笔不留扣减。
- `refund_race_test.go`：跨批次销售后并发超额部分退款，成功退款不超额、
  回到原来源、原凭据不变，补退到全额后各来源重量完全冲回。
- `snapshot_test.go`：暂停在校验后提交前的分装不阻塞不相交写；
  跨批次销售与快照受控交错，快照只对应整笔交易之前或之后。
- `stress_test.go`：混合并发下每次快照都满足账务不变量。
