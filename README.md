# weightledger

进程内并发的种植-分装-销售重量账本（Go）。重量统一为整数厘克（1 厘克 = 0.01 克），
数据全部在内存，无持久化。

## 操作

- `Package(batchID, sku, units, waste)`：从种植批次散装余额扣除 `单件净重*units + waste`，
  生成唯一递增库存批号，余额以整件计。
- `Sell(lines)`：一笔销售可含多个 SKU，同 SKU 按库存批号升序扣减，可跨来源批次；
  返回不可变销售凭据。
- `Refund(saleID, lines)`：按原销售凭据的分配顺序 FIFO 退回原库存批号，
  返回关联原销售的不可变退款凭据，不改写原凭据；退回商品可再次销售。
- `Snapshot()`：批次重量账户、库存批号余额、销售与退款凭据的一致视图，
  返回后不随后续写入变化。

## 并发设计

- 无全局业务锁：批次、SKU、凭据存储各自加锁；嵌套加锁顺序固定为
  批次 → SKU（按字典序）→ 凭据存储，写操作先校验后提交，失败不留任何变化。
- `Snapshot` 使用各分区单调版本号：采样版本 → 逐分区局部锁读取 → 复核版本，
  不一致则重试；不暂停写入、不等待写操作结束。
- 每个快照满足：批次初始重量 = 剩余散装 + 在库包装净重 + 净已售 + 累计废弃，
  各项非负；在库净重与净已售可由同快照的库存余额与凭据复核。

## 测试

```sh
go test ./...        # 全部测试
go test -race ./...  # 竞态检测
```

并发交错通过 `SetHook` 测试钩子（校验通过后/提交前、快照扫描前）与 channel 屏障控制，
不使用固定 sleep。覆盖：反向 SKU 顺序竞争同一库存、跨批次销售的超额并发退款、
暂停分装期间不相交写可完成、快照读取期间发生跨批次销售的一致性。
